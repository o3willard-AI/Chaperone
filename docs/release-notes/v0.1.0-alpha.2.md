# Chaperone v0.1.0-alpha.2

Second individual preview. **Hardening + install experience** release on top
of alpha.1's feature set (all four mechanisms, policy, audit chain, vault,
confirmation gate).

## Security fixes & hardening

- **Replay-journal capacity (D34)**: nonce reservations are journaled before
  signature verification by design; that journal now has a hard byte cap.
  Flood attempts fail closed (`E_REPLAY`, self-healing) instead of growing
  disk without bound.
- **Elevated allowlist ownership enforcement**: `chaperone-helper --elevated`
  refuses allowlist files that are not root-owned / not group-or-other
  writable - closing an arbitrary-root-exec footgun in the sudoers
  deployment path.
- Error chains from PostgreSQL now walk to the server-side message.

## Install experience (new)

- Per-user installers for Linux/macOS/Windows: binaries, service
  definitions (systemd user unit / launchd agent / logon task), config
  skeleton, and a post-install checklist. See [INSTALL.md](../INSTALL.md).
- `--passphrase-file` for headless vault unlock.
- `chaperone version` / `--version`.

## Connectivity additions since alpha.1

- db-scram against PostgreSQL (one-shot + SQL sessions).
- HashiCorp Vault KV-v2 provider (`vault://`).
- SSH host-key pin store with TOFU + known_hosts import.
- Operator console socket; GitHub API worked example (tested).

## Verification

Same trust boundary as alpha.1: sha256 manifest + ed25519 detached
signatures, reproducible builds; no corporate OS codesigning yet.
[RELEASE.md](../RELEASE.md) has the verify steps and public key.
