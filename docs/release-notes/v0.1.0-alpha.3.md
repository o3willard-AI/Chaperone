# Chaperone v0.1.0-alpha.3

Third individual preview. **The operator-facing release**: a local config
UI, a live notification feed, and a policy-file integrity guard - the
response to first-run user acceptance testing, where the model's first
real-world failure mode turned out to be "a user asking their agent to
configure its own leash" (OPERATOR-UI-SPEC §1).

## New: operator config UI (M14c)

`chaperone serve` now serves a loopback web UI (default
`http://127.0.0.1:8720`, `--ui-port N`, `--no-ui` to disable):

- **Setup wizard** on first run: with no vault/policy/audit key present,
  serve starts in setup-only mode and walks through creating exactly the
  files GETTING-STARTED.md used to walk by hand.
- **Secret CRUD** that never re-displays a stored value (`[redacted] N
  bytes present`, rotation = store same path again).
- **Rule editor** with mechanism picker + service templates carrying the
  CONNECTIVITY-MATRIX maturity badges and caveats inline. Generated TOML is
  produced by `Policy::to_toml` and re-validated by `Policy::from_toml`
  before it touches disk - one validator, two front ends; no second parser
  exists anywhere.
- **Agent enrollment** with client-side public-key validation (the
  "pasted the whole JSON blob" mistake gets a specific error), plus
  revoke.
- Raw TOML editor for the twelve people who like reading TOML.

Posture: server-rendered HTML/CSS, zero JavaScript build step, bound to
127.0.0.1 only, no login/token (same trust tier as the console client),
with a Host/Origin guard closing browser CSRF/DNS-rebinding paths (D40).

## New: live event feed wiring (completes M14b)

`chaperone serve --events-socket PATH` now binds the read-only fan-out
socket from alpha.3's D35 work, making per-decision notifications actually
reachable by `tail`-style subscribers.

## Security: policy-file integrity guard (D39, new)

Two layers over the ruleset-hash anchoring shipped in M14a:

- **Load-time permission gate**: a `policy.toml` that is group/other-writable
  or owned by another account refuses to load, with a remediation-shaped
  message.
- **Live drift watch**: any change to the governing file under a *running*
  gateway - edit, replace, deletion - appends one signed `policy_drift`
  record to the audit chain, broadcasts on the events feed, prints a loud
  banner, and **halts brokering** until an operator restarts. An edited
  rule can never take effect silently; the restart re-runs the gate and
  re-anchors the chain.

Honest limit (unchanged): this detects and stops; nothing can physically
prevent a same-user writer from editing the file. Fail-closed direction
chosen deliberately over watch-baseline updates.

## Policy crate

- Canonical TOML writer (`Policy::to_toml`) beside the one parser, with
  round-trip guarantees for every matcher kind.
- New `exact:` matcher tag so literals containing `*` can be expressed as
  exact matches (previously impossible); lossless serialization for all
  kinds (`glob:`-tagged wildcard-less globs included).
- `Policy::rules()` accessor for operator tooling.

## Docs

- **GETTING-STARTED.md** (finally written): zero-to-brokered-action via
  the wizard, CLI equivalents at every step.
- DESIGN-DECISIONS.md: D35-D40 recorded (event feed transport, UI thin
  client, notify-default-on, hash anchoring, integrity guard, UI shape).
- PLAN.md Phase 14 entry with acceptance tests.

## Upgrade notes

- `policy.toml` must not be group/other-writable anymore; `chmod go-w`
  if upgrading from loose modes.
- Editing policy while serving now halts the gateway until restart -
  intentional (see above).
- The config UI listens on 127.0.0.1:8720 when serve runs; use `--no-ui`
  if you do not want it.

Full verification instructions: [docs/RELEASE.md](RELEASE.md). Expect
breaking changes while specs remain v0.1 drafts.
