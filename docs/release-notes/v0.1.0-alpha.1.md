# Chaperone v0.1.0-alpha.1 — individual preview

The first packaged build of Chaperone: a local-first authentication broker
that lets an AI agent perform authenticated operations against other systems
**without any credential ever entering the agent's context, transport, or
logs.** The agent holds a reference, never a secret.

This is an **early preview for individuals** to exercise and evaluate.
Pre-release software; expect rough edges and breaking changes.

## What works

- **Signed intents**: Ed25519 per-agent keys (platform key store custody),
  JCS canonicalization, strict §4 verification order, replay journal that
  survives restarts.
- **Default-deny policy engine**: declarative TOML rules over agent ×
  cred_ref × target × mechanism; first-match wins; constraints only narrow.
- **Mechanisms**: `http-bearer` / `http-basic` (one-shot), `ssh` sessions,
  `db-scram` against PostgreSQL (real SCRAM-SHA-256), `local-privilege`
  through the separate pinned allowlist helper.
- **HashiCorp Vault KV-v2** (`vault://`) alongside the built-in encrypted
  local vault (`local://`, argon2id+AES-GCM sealed).
- **Audit chain**: append-only, hash-chained, ed25519-signed evidence with
  zero secret material - verified by `chaperone audit-verify`.
- **Single confirmation gate**: operator console socket or TTY.

## Quick start

```sh
cargo install --locked --path crates/cli          # or download a release archive
chaperone audit-keygen --out ~/.config/chaperone/release.key
chaperone vault-init   --store ~/.config/chaperone/vault.bin
chaperone enroll       --store ~/.config/chaperone/enrollment.json \
                       --agent-id agent:first --public-key <agent pubkey>
printf 'pass\nyour-api-token\n' | chaperone vault-set \
                       --store ~/.config/chaperone/vault.bin \
                       --path prod/stripe/key --passphrase-stdin
chaperone serve        --enrollment ~/.config/chaperone/enrollment.json \
                       --policy policy.toml \
                       --store    ~/.config/chaperone/vault.bin \
                       --audit-journal ~/.config/chaperone/audit.jsonl \
                       --audit-key     ~/.config/chaperone/release.key
```

Agents speak Content-Length-framed JSON to `$XDG_RUNTIME_DIR/chaperone/gw.sock`
- see [`docs/skill/SKILL.md`](https://github.com/o3willard-AI/Chaperone/blob/main/docs/skill/SKILL.md)
and the [intent catalog](https://github.com/o3willard-AI/Chaperone/blob/main/docs/skill/references/intent-catalog.md).

## Security posture - read before running

- Artifacts carry **our ed25519 signatures + sha256 manifest**, and builds
  are reproducible. They do NOT carry corporate OS code signing yet
  (Authenticode / Apple notarization) - expect Gatekeeper/SmartScreen
  prompts. Verify instead of clicking through:
  [docs/RELEASE.md](https://github.com/o3willard-AI/Chaperone/blob/main/docs/RELEASE.md).
- The gateway process is the trusted computing base; a root-level local
  attacker is out of scope by design. Full honesty in the
  [threat model](https://github.com/o3willard-AI/Chaperone/blob/main/docs/03-threat-model.md).
- Known gaps, stated: no TLS to PostgreSQL yet; db host-key pin store covers
  SSH but not other protocols; Windows console socket pending.

Everything is Apache-2.0, built in the open. Report vulnerabilities privately
per [SECURITY.md](https://github.com/o3willard-AI/Chaperone/blob/main/SECURITY.md).
