# Chaperone v0.1.0-alpha.4

Security follow-up to alpha.3. Closes the loopback-UI access gap flagged
in OPERATOR-UI-SPEC §8: a plain TCP listener on 127.0.0.1 has no OS-level
per-user ACL (unlike the `0600` Unix domain sockets every other Chaperone
surface uses), so any local OS account — not just the one that configured
Chaperone — could reach the config UI and drive the full surface.

## Security fix: per-instance UI access token (D41)

- **New:** a 32-byte random access token (base64url), created once via
  `chaperone ui-token rotate --token <PATH>`, persisted at `0600` in the
  config directory alongside `audit.key`. The token inherits the
  directory's existing owner restriction on all three target platforms —
  no new platform-specific socket/pipe ACL code.
- **`chaperone serve` refuses to start the UI** until the token file
  exists. Never auto-generates, never prints the token. This prevents the
  browser-based wizard from having to create its own gate.
- **Enforcement:** first load needs `?token=…`; the UI sets a scoped
  `HttpOnly; SameSite=Strict` cookie and strips the token from the URL.
  Subsequent requests use the cookie. Any request without a valid token
  or cookie: GET → paste page (approachable, not a bare 403); non-GET →
  403.
- **Constant-time comparison** prevents timing-based token recovery.
- **Layering preserved:** the D40 Host/Origin guard stays as the outer
  layer (answers "which origin" — CSRF/DNS-rebinding); the token is the
  inner layer (answers "which local account"). A foreign Host is refused
  even with a valid cookie.

## New CLI subcommands

```
chaperone ui-token show   --token <PATH>     # prints token + URL
chaperone ui-token rotate --token <PATH>     # generates/overwrites, prints URL
```

## New serve flag

`--ui-token PATH` — defaults to `<audit-key-dir>/ui.token`.

## Upgrade from alpha.3

If you were running the config UI without a token:

```console
$ chaperone ui-token rotate --token ~/.config/chaperone/ui.token
$ chaperone serve ...    # same command as before
```

`serve` will refuse to start the UI until the token exists; the error
message points at the exact command to run.
